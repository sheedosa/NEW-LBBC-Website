# LBBC Content Manager (CMS) — Setup & Usage

The website now has a built-in content manager (Sveltia CMS) at **https://lbbc.org.uk/admin**.
Editors sign in with GitHub and can edit almost everything on the site through simple forms.
Saving a change commits it to this repository, which automatically rebuilds and republishes the
site in about a minute.

**Not editable here (on purpose):** the **Member Directory** and **Events** — those sync
automatically every day from GlueUp.

---

## One-time setup (technical, ~15 minutes)

The admin login needs a tiny free "login helper" because GitHub Pages can't run server code.
You only do this once.

### 1. Create a GitHub OAuth App
1. Go to **GitHub → Settings → Developer settings → OAuth Apps → New OAuth App**.
2. Fill in:
   - **Application name:** `LBBC CMS`
   - **Homepage URL:** `https://lbbc.org.uk`
   - **Authorization callback URL:** `https://lbbc-cms-auth.<your-subdomain>.workers.dev/callback`
     (you'll get this exact URL in step 2 — you can come back and paste it).
3. Click **Register application**. Copy the **Client ID**, then **Generate a new client secret** and copy it.

### 2. Deploy the free login helper (Cloudflare Worker)
Requires a free Cloudflare account and Node installed locally.
```bash
git clone https://github.com/sveltia/sveltia-cms-auth.git
cd sveltia-cms-auth
npx wrangler login
npx wrangler deploy
# then set the three secrets/vars:
npx wrangler secret put GITHUB_CLIENT_ID       # paste Client ID
npx wrangler secret put GITHUB_CLIENT_SECRET   # paste Client secret
npx wrangler secret put ALLOWED_DOMAINS        # enter: lbbc.org.uk
```
`wrangler deploy` prints the Worker URL, e.g. `https://lbbc-cms-auth.yourname.workers.dev`.
Use that URL as the callback base in step 1 (`.../callback`).

### 3. Point the CMS at the login helper
Edit **`public/admin/config.yml`** → `backend.base_url` and replace the placeholder with your
Worker URL (no trailing slash):
```yaml
backend:
  name: github
  repo: sheedosa/NEW-LBBC-Website
  branch: main
  base_url: https://lbbc-cms-auth.yourname.workers.dev
```
Commit & push (or let the CMS itself save it later). The site redeploys automatically.

> Note: `config.yml` is generated by `scripts/gen-cms-config.mjs`. If you regenerate it, set
> `base_url` again (or edit the script's placeholder once).

### 4. Invite editors
**GitHub → this repo → Settings → Collaborators → Add people**, give them **Write** access.
Each editor needs a free GitHub account. That's the only account they need.

## Using the CMS (for editors)
1. Go to **https://lbbc.org.uk/admin** and click **Sign in with GitHub**.
2. Pick a section on the left (News, Website Text, Team, Site Settings, …).
3. Edit the fields, then **Save**. Your change goes live in ~1 minute.

**Tips**
- **News:** each article has a title, date, category, image, and a rich text body.
- **Website Text (English & Arabic):** all page wording. Some entries contain `{name}` /
  `{role}` / `{tab}` placeholders — leave those exactly as they are.
- **Images:** use the image picker; uploads are saved into the site automatically.
- If you add or remove a **hero slide**, do it in both **Homepage Hero** (image/links) and
  **Website Text → hero** (the wording) so they stay matched.

## Local testing (optional, for developers)
```bash
# 1. temporarily add `local_backend: true` to public/admin/config.yml
# 2. run the local commit proxy:
npx @sveltia/cms-proxy-server     # or: npx decap-server
# 3. in another terminal:
npx vite
# 4. open http://localhost:5173/admin/ , edit something, Save,
#    and confirm the matching file under content/ changed on disk.
```
Remove `local_backend: true` before committing.

## How it fits together
- Editable content lives in **`content/`** (Markdown + JSON). The app imports it at build time,
  so the rendered site is identical to before — just sourced from files the CMS can edit.
- GlueUp data stays in **`public/data/`** and is refreshed by the daily scraper workflow; the CMS
  never touches it. The scraper rebases before pushing so CMS edits and data refreshes never clash.
